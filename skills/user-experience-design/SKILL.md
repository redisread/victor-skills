# user-experience-design

> 用户体验设计方法框架。基于 B. Joseph Pine II & James H. Gilmore《体验经济》的核心思想，把体验从「产品/服务的附属品」升级为「独立的价值载体」。在开始任何产品或界面设计前先跑一遍本 skill，建立体验目标，再让 UI/视觉/文案落地。

## 使用时机

**必用**（在这些场景之前先跑本 skill）：
- 接到「新产品/新功能」需求，做 spec 或线框图之前
- 已有产品要做「体验升级/改版」，先诊断再动手
- 分析某个用户流失点、投诉集中的触点
- 决定营销/推广走什么内容策略（体验先于渠道）

**可选**：单点视觉修复、纯规范落地、Bug fix——这类不需要跑完整框架，但可用第 4 条「顾客损失」快速自检。

## 输入 → 输出

输入至少给到：
- 产品/触点/流程的一句话描述
- 目标用户群体（一句话画像）
- 当前的核心指标或痛点（如果有）

输出交付：
1. **体验目标一句话**（这次交付要给用户什么感觉/记忆点）
2. **顾客损失清单**（用户勉强接受的 3-5 项现实 → 内心期望）
3. **主题构思**（这次体验的一致性主题是什么）
4. **游戏化/记忆点设计**（1-2 个正面回忆制造装置）
5. **定制化机会**（哪几处可以脱离千篇一律）
6. **落地清单**（交给 UI/视觉/文案的可执行 brief）

## 8 条核心思想（方法框架）

### 1. 体验式营销：产品即体验

> 把体验营造应用到产品和服务的营销中，努力消除对传统媒体的依赖。

产品本身就是最大的传播媒介。设计任何触点时先问：**「用户在这里的体验能不能自己变成传播内容？」** 如果需要靠信息流广告或推送硬推，说明体验本身没做到位。

**应用检查**：
- 用户使用后有没有自发分享的动力？（截图/发朋友圈/推荐给朋友）
- 分享出去的内容能否传达产品的核心气质？
- 如果拿掉所有营销预算，产品自己能不能长出来？

### 2. 客户体验管理（CEM）

> 目的是向顾客提供更友好、更轻松、更便捷的互动。

CEM 不是 CRM——不是管理客户数据，是管理**客户与产品/服务每一次接触的感受**。

**旅程扫描法**：把用户从「第一次听说」到「离开产品」的所有接触点列出来（认知→下载→注册→首次使用→常规使用→遇到问题→离开），逐点打分（1-5）：
- 友好度：这一步是不是「站在用户这边」？
- 轻松度：需要几步？有没有必填但没意义的字段？
- 便捷度：能不能一步完成？有没有让用户猜？

低分项优先优化，不是均匀铺开。

### 3. 数字化体验

> 数字化体验的探索。

数字触点具有物理触点没有的能力：**可变形、可记忆、可协作、可个性化**。做数字体验时充分用满这些能力，别把 App 做成纸质表单的电子版。

**几个提问**：
- 这个界面能不能根据用户上次的行为变化？
- 系统记不记得用户的偏好？下次来时会不会「认识」他？
- 有没有可能让两个用户在此协作而不是各用各的？
- 有什么是数字才能做、纸质做不了的？

### 4. 定制化（Mass Customization）

> 定制化也是提高用户体验的一种方式，不要做千篇一律、毫无特色的产品。

定制化不等于「让用户选皮肤」。真正的定制化是**在关键触点上给出反映用户身份/偏好/情境的差异**。

**层级递进**：
- L1 表层定制：主题、字号、快捷键（成本低，感知也低）
- L2 内容定制：首页推荐、默认设置、常用入口（有价值，多数产品到此为止）
- L3 结构定制：不同用户看到完全不同的功能布局（高价值，需要用户模型）
- L4 时序定制：同一个用户在不同时间/情境看到不同界面（最高级，需要行为预测）

一般产品从 L2 开始有回报，L3-L4 是差异化护城河。

### 5. 顾客损失（Customer Sacrifice）

> 顾客损失是指每一个勉强接受的现实（购买的产品和服务）和他们内心期望的最佳体验之间的差距。哪个方面的顾客损失一旦消除会给消费者带来巨大价值？

**这是全书最锋利的工具**。用户从来不会自己说「我损失了什么」，他们只会「勉强用着」。设计者的任务是**主动挖顾客损失**。

**挖掘方法**：
1. 列出用户使用产品的完整流程
2. 每一步问：「用户理想中这里应该是什么样？」
3. 对比现实：「现在这里是什么样？」
4. 差距 = 顾客损失
5. 按「消除后价值大小 × 消除难度」排序

**典型顾客损失清单**（可作模板起点）：
- 我知道我要什么，但要点 5 次才能拿到
- 我上次告诉过系统一次，这次它又问一遍
- 我只想快速完成一件事，你却给我看了 10 个功能
- 我需要它记得我的上下文，它每次都从零开始
- 我这一步做错了，恢复成本很高
- 别人都在用，只有我一个人干这件事很孤独

**消除顾客损失比新加功能价值大得多。**

### 6. 记忆点设计

> 并不是每一次体验都需要强烈回忆，但如果它制造的正面回忆越多，持续时间越久，那它创造的价值就越大。

记忆点服从**峰终定律**（Peak-End Rule）：用户对一次体验的整体评价，主要由两个瞬间决定——**最高点** + **结束点**。

**记忆点设计三步**：
1. 找出这次体验的自然「峰」在哪一步（通常是完成核心目标的瞬间）
2. 让「峰」比日常水平高一到两个级差（动效、文案、意外的反馈）
3. 强化「终」——用户离开产品前最后 3 秒看到什么、感受到什么

**反例**：把资源均匀分散在整个流程上，每一步都做得「还行」——用户走完毫无记忆，因为没有峰。

**正例**：GitHub 的绿色 commit 方块、Duolingo 的连胜火焰、Notion 的第一次「/」命令——都是精心设计的「峰」。

### 7. 游戏化 + 新的游戏内容

> 实现体验化的两种方式：游戏化体验 + 创造新的游戏内容。

游戏化不是「加积分和徽章」——那是最初级的游戏化，且往往适得其反（外部激励挤出内部动机）。**真正的游戏化是把使用产品变成一件本身有乐趣的事**。

**游戏化的四个层次**：
- L1 徽章积分：外部激励，短期有效，长期反效果
- L2 进度可见：让用户看到自己的成长（提交历史、掌握度地图）
- L3 挑战机制：设置合理难度的任务，用户主动追求
- L4 心流状态：产品本身变成「玩得停不下来」的体验

**创造新的游戏内容**：产品可以定期推出「玩法更新」——新模式、新场景、新协作——让老用户有回来的理由。这是 SaaS 时代的核心保留手段。

### 8. 主题化（Theming）

> 为体验构思主题。

**没有主题的体验只是功能集合**。主题是把所有触点串起来的隐喻/氛围/叙事——让用户在使用过程中感受到一种「氛围一致性」。

**主题构思三问**：
1. 如果这次体验是一个「场所」（餐厅/图书馆/工坊），它应该是什么？
2. 如果这次体验是一个「角色扮演」，用户是谁？（学徒/探险家/收藏家/主人）
3. 如果这次体验有一句「slogan」，它是什么？（不是营销 slogan，是内部指南）

主题一旦确定，所有 UI/文案/动效/命名都要贴着它走。**主题决策比视觉决策更早**。

**例子**：
- Linear：主题是「工程师的键盘操作台」→ 所有交互围绕键盘展开
- Airbnb：主题是「归属感」→ 所有文案避免「租客/房东」、用「主人/客人」
- Duolingo：主题是「游戏化课堂」→ 角色 + 关卡 + 血量

## 交付前的自检清单

在把体验设计输出给 UI/Martin 之前，自问：

- [ ] 我能用一句话说清这次体验的目标吗？
- [ ] 顾客损失清单至少列了 3 项吗？每一项都有具体的用户行为证据吗？
- [ ] 主题定了吗？UI 决策能不能从主题推导出来？
- [ ] 有没有至少 1 个明确的「峰」设计？
- [ ] 有没有至少 1 处定制化机会？
- [ ] 落地清单是给 UI/Martin 可以直接开始工作的形式吗？

## 与其他技能/角色的配合

- **本 skill → frontend-design skill**：先跑体验设计得出「主题 + 记忆点 + 顾客损失」，再让 frontend-design 决定视觉/字体/布局。**体验决定视觉，反过来不行。**
- **本 skill → Martin**：把「落地清单」作为需求 spec 给 Martin，让他拆任务
- **本 skill → 卢曼**：主题和记忆点也是内容/文案的输入——写产品页文案、发布推文时保持主题一致

## 反模式（避免这样用本 skill）

- 拿本 skill 的 8 条思想去做形式化打分表，让 UI 迎合分数（会导致模板化）
- 把定制化理解成「让用户勾选很多选项」（真定制是系统自己知道）
- 加积分徽章然后叫它「游戏化」（那是 L1，往往负价值）
- 主题选了但落地时没坚持（每个决策都要过一遍主题）
- 顾客损失清单只列，不排序，不选优先（清单本身没用，排序才有）
- **主题化 = 换 UI 配色**：真主题是从用户视角出发的隐喻/角色/场所（「地点即一切」/「印刷粗野」/「放映厅」），UI 配色只是主题落地的其中一层。别把「换个配色」当成主题化交付
