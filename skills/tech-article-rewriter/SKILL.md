# 科技文章编译器

把英文报告、机器翻译稿、会议或直播转写，编译成逻辑清楚、读感自然、信息密度高的中文科技文章。这里的“编译”不是逐句直译，也不是替素材补写事实，而是在不改变证据边界的前提下重建文章结构。

## 适用场景

- 英文技术报告、研究文章或产品分析需要改写成中文文章
- 机器翻译稿需要去翻译腔、补足上下文和重建段落逻辑
- 会议、播客或直播文字稿需要清理口语噪音并整理成稿
- 中英混合素材需要统一术语、数字和叙述口径

不负责自动抓取来源、外部事实核查、学术论文定稿、广告文案或自动发布。素材涉及来源不明的事实时，保留来源边界，不把改写误报为独立核验。

## 输入预检

开始写作前，先确认并记录：

- 素材类型：报告、文章、机器译文、访谈、直播或字幕
- 来源、作者、日期、原文链接和可见的引用信息
- 目标读者、预期篇幅、文章用途和是否保留图片 Markdown

缺失的元数据不要猜。若素材存在多个互不相容的主题，先询问用户希望的主线；若只是同一主题的不同材料，合并时标记冲突和来源。

## 编译流程

### 1. 建立事实底稿

先提取“主张—证据—限定语—出处”，并给每项内容标注性质：事实、观点、推测、传闻、营销表述或无法确认。重点记录：

- 人名、机构名、产品名、版本号、代码和专有名词
- 数字、单位、时间、比例、样本规模和比较基准
- 因果关系、条件、概率、引用归属和“可能”“据称”等模态
- 转写中的听不清、说话人切换、上下文缺失和前后矛盾

这一步的目的是防止“写得更顺”变成“写出了原文没有的结论”。

### 2. 选择文章主线

优先按信息价值重排，而不是机械保留报告章节或发言时间顺序。默认结构如下，可按素材删减：

1. 核心发现或读者最需要知道的问题
2. 必要背景
3. 机制、证据或案例
4. 对行业、产品或实践的影响
5. 局限、争议和未知部分
6. 读者可以采取的具体行动

开头直接给出具体事实、数据或矛盾，不用“这是一个反直觉的结论”之类的标签替读者下判断。小标题要表达实际内容，不使用“背景介绍”“数据分析”等空标题。

### 3. 翻译与重写

- 按意义和上下文转换，不逐句复制英文语序
- 首次出现的关键术语用“中文（English）”，后续保持同一译法
- 保留原文的数字、单位、版本、代码、引用归属、概率和限定语
- 直接陈述事实和观点，让信息本身产生冲击，不用情绪预告或夸张钩子
- 目标读者有技术背景但时间有限：短段落，一段只承担一个主要观点，解释复杂概念时使用准确的生活化类比
- 全程使用第三人称和中文标点，除代码、命令、URL、专名等必要内容外，不混用英文标点

### 4. 清理转写噪音

删除 filler、重启、口头重复、无信息寒暄、导播提示和明显的识别噪音；合并同一说话人的碎片表达。但以下内容必须保留：

- 关键问答、分歧、反例和观点转折
- 原文中的犹豫、猜测、条件和不确定性
- 能改变含义的时间戳、数字或说话人归属

无法判断的内容标为“原文未说明”“此处听不清”或列入存疑点，不要根据常识自行补全。

## 输出格式

默认交付以下结构：

```markdown
# 具体、不过度夸张的标题

可选导语：用 1—2 句交代核心事实或问题。

正文……

## 来源与编译说明

- 来源：作者、标题、链接或“用户未提供”
- 素材类型：原文、机器翻译稿、访谈转写等
- 存疑点：无法确认的数字、术语、因果或转写片段
```

用户明确要求“只给成稿”时，隐藏“来源与编译说明”这一节，但仍要在交付前完成内部核验。原文中的图片 Markdown 引用要原样保留，并放在与原文语境相符的位置；无法确认位置时不要擅自移动到文末。

## 表达约束

避免以下高频 AI 腔和空洞套话：

- “不是……而是……”
- “想象一下”“你有没有想过”
- “值得注意的是”“不难理解”“毋庸置疑”
- “随着……的发展”“对于……来说”“在……方面”
- “精准打击”“赋能”“落地”“深度融合”“全面布局”“强势崛起”
- “最让我吃惊的是”“最扎心的是”“最意外的是”等没有具体证据支撑的情绪预告
- “这是一个……”“这不是一个……”等先贴标签、后解释内容的开场

这些不是机械禁词表：如果原文中的直接引语确实包含它们，保留引语并注明归属；如果某个表达在具体语境中不可替代，优先保证事实和自然度。

## 交付前自检

- [ ] 标题具体，开头靠事实、数据或问题建立阅读动机
- [ ] 每个数字都有正确的单位、范围、时间和比较基准
- [ ] 专名、术语、版本和引用归属前后一致
- [ ] 因果关系没有被改写成原文未声称的因果
- [ ] “可能”“据称”“估计”等限定语没有被删除或增强
- [ ] 没有把推测、广告或转写猜测写成事实
- [ ] 每段只承担一个主要观点，段落之间有清楚的因果或递进关系
- [ ] 删除了翻译腔、口语噪音、重复和无信息套话
- [ ] 图片引用、代码、命令和 URL 被保留且位置合理
- [ ] 无法确认的部分已明确标记，没有自行补全
- [ ] 来源和编译状态已说明，除非用户要求只输出成稿
