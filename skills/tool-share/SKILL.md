# Tool Share

根据用户提供的工具名称，调研并生成一篇结构化的工具分享文章。

## 工作流程

### 1. 收集工具信息

向用户确认以下信息：
- **工具名称**（必填）
- **工具类型**：CLI工具 / 框架 / 库 / SaaS / IDE插件 / 其他
- **主要用途**：一句话描述这个工具解决什么问题
- **技术栈**：如 Java、Python、Node.js 等

如果用户已经提供了足够的信息，直接进入下一步。

### 2. 调研工具信息

使用 WebSearch 和 WebFetch 调研以下内容：

1. **官网与文档**
   - 官方网站链接
   - 官方文档链接
   - GitHub/GitLab 仓库链接

2. **基本使用**
   - 安装方式（包管理命令、下载链接等）
   - 快速开始示例（Hello World 或最小可用示例）
   - 核心 API 或命令概览

3. **最佳实践**
   - 社区推荐的使用模式
   - 常见陷阱与注意事项
   - 性能优化建议

### 3. 生成分享文章

使用以下模板生成文章：

```markdown
# {工具名称} — {一句话描述}

> {工具的 slogan 或核心定位}

## 基本信息

| 项目 | 内容 |
|------|------|
| 官网 | {链接} |
| 文档 | {链接} |
| 源码 | {GitHub 链接} |
| 版本 | {当前最新稳定版本} |
| 许可证 | {License 类型} |

## 它是什么？

{2-3 段介绍：这个工具的背景、解决了什么痛点、为什么值得关注}

## 快速开始

## 输出方式

文章生成后，询问用户希望如何保存：

1. **直接输出到终端** — 直接在对话中展示
2. **保存为文件** — 保存为 `tool-share-{工具名}.md` 到当前目录
3. **发布到知识库** — 使用 KM MCP 发布到美团知识库

## 注意事项

- 所有链接必须是经过验证的真实链接，不编造 URL
- 代码示例必须语法正确、可以运行
- 最佳实践和陷阱应来自官方文档或社区共识，标注来源
- 文章语言为中文，技术术语保持英文原文
- 如果工具较新或信息有限，明确标注"信息截至调研日期"
